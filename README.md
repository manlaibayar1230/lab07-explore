## Хэсэг E: Дүгнэлт (debrief)

Хамгийн үр дүнтэй нь **Guidebook** аялал байсан: спецификацийн 8 дүрмийг нэг нэгээр нь шалгахад тоолуур (BUG-03), хуучин хувилбарын линк (BUG-05), онгийн хүрээ (BUG-07), хайлт (BUG-09), устгах мессеж (BUG-10) гэсэн 5 согог олдсон. **Supermodel** нь кодгүй, зөвхөн харахад л онгийн формат (BUG-01), ногоон «Устгах» (BUG-02), латин «x» (BUG-04) гэсэн 3 согогийг өгч, BUG-05-ын линкийг анзааруулсан. **Couch Potato** хоосон формоор (BUG-06), **Obsessive-Compulsive** давтан нэмэлтээр (BUG-08), **Antisocial** урт гарчгаар (BUG-11), **Saboteur** `curl`-ээр буруу JSON-оор (BUG-12) тус бүр нэг согог илрүүлсэн. Charter-аас гадуур санамсаргүй олдсон зүйл нь устгах мессеж (эхэндээ хуучин мессеж үлдсэн гэж бодоод reload хийж байж буруу мессеж гэдгийг ойлгосон), API онг текстээр хадгалдаг явдал, мөн HTML оролтын давхар escape байлаа. Шалгагдаагүй үлдсэн нь гарын товчлуураар (Enter, Tab) ашиглах, гар утасны өргөн, олон хэрэглэгч зэрэг засах, маш олон (1000+) ном, тусгай Unicode (emoji, RTL) оролт, хайлтын хоосон/зайтай үг зэрэг бөгөөд эдгээр нь дараагийн session-ий charter болно. Лаб 1-ийн **Playwright** автомат тестээр баригдах байсан нь тодорхой утга шалгах согогууд: тоолуур (BUG-03 — мөрийн тоо ба текстийг тулгах), 500 хуудас (BUG-05), заавал талбар, хүрээ, давхардал (BUG-06/07/08), хайлт (BUG-09), мессеж (BUG-10), API статус (BUG-12), мөн «1999» текст хүлээвэл BUG-01; BUG-04 нь `getByRole('button', {name: 'Нэмэх'})` товч олдохгүй болж санамсаргүй баригдана. Харин ногоон «Устгах» (BUG-02) ба урт текстэд эвдрэх хүснэгт (BUG-11) нь функциональ assertion-д PASS болох тул зөвхөн хүний нүд эсвэл visual regression (скриншот харьцуулалт) тестээр олдоно. Гэхдээ автомат тест нь хэн нэгэн тухайн дүрмийг урьдчилан assertion болгож бичсэн үед л барих тул эдгээр согогийг эхлээд олж, дүрэм болгон томьёолоход exploratory тест хэрэгтэй гэдгийг энэ session харууллаа.
